# OpenWallstreet

Live site: [wallstreet-leadership.zishenchan.workers.dev](https://wallstreet-leadership.zishenchan.workers.dev)

A Next.js App Router application running on vinext and Cloudflare Workers. It preserves the existing leadership UI's off-white theme, perspective timeline, staged card motion, four separate assessments, source disclosures, and coverage limitations. The homepage contains company research, public example cards, and Reception. Alphabet and Microsoft examples have dedicated pages; they are historical evidence, not current investment guidance.

## Run

From `src/web`:

```sh
npm ci
npm run types
npm run typecheck
npm test
npm run dev
```

`npm run build` creates the Worker and static assets. `npm run start` previews that production output locally. `npm run deploy:dry-run` checks an existing build; `npm run deploy` builds and deploys `wallstreet-leadership` to the account in `wrangler.jsonc`.

## Reusable UI

- `components/ResearchWorkspace.tsx`: company input, submission, progress, polling, retry, and session recovery. Completed jobs open at `/research/{id}`.
- `components/report/LeadershipReport.tsx`: the public report component. Pass a validated `LeadershipReport` object. Mount with a new React key when replacing a report to reset selection.
- `AssessmentGrid`, `EvidenceTimeline`, `EventCard`, `Evidence`, and `CoverageDisclosure`: independently organized report sections. They consume `ReportProvider`; no company data is embedded in these components.
- The timeline switches between Perspective and List while retaining the selected milestone. The list supports chronological scrolling, year shortcuts, and inline evidence. Content fades out before the shared rail morphs, then returns after the rail settles. Switching is interruptible; reduced motion changes views immediately. Motion settings live in `components/report/timeline-views.css`.
- `lib/report-schema.ts`: TypeScript types and runtime validation for company input, reports, and asynchronous jobs.
- `lib/job-service.ts`: server-only job-service integration. Only API handlers import it.
- `data/alphabet.json`: a copy of the original compiled `../leadership-ui/evidence-model.json`, with a public ledger link and normalized scope punctuation. The original evidence files are unchanged.
- `data/report.schema.json` and `data/job.schema.json`: portable contracts generated by `npm run schema`. Runtime validation additionally checks evidence references, unique IDs, event chronology, and timeline span.

The original Python compiler remains the source of Alphabet evidence. Run `npm run sample:refresh` after recompiling the original evidence, then rerun validation. The refresh script validates the sample and makes local provenance paths repository-relative in the public ledger. Do not treat the sample cutoff or provisional interpretations as current facts.

## Live Cloudflare research

The website connects privately to `wallstreet-research` through a Cloudflare service binding. A durable Workflow runs three fiscal-year research workers concurrently, using the Nebius NVIDIA model and Tavily. D1 stores job state, search records, extracted source text, verified quotations, and the final report. Closing the browser does not stop research.

Visitors can create a private research code through Reception. The administrative `RESEARCH_ACCESS_CODE` saved in the repository's ignored `.env.cloudflare` file remains available for the owner. Supported issuers are Apple, Microsoft, Alphabet, Amazon, NVIDIA, Meta, and Tesla. The deployment targets the paid account `2e7eb340166ebda1a90cc2ee6c589c52`. The research Worker explicitly allows 30,000 ms of CPU per invocation; this avoids the previous free-plan 10 ms limit during document processing.

The live scope is the three completed calendar-year labels before the run year, with at most one annual report per fiscal year and six extraction chunks per report. This is an evidence inventory, not the full Python leadership assessment: it does not score honesty, infer individual responsibility, or decide whether promises were fulfilled. Missing reports and partial extraction appear in the coverage disclosure.

Results resume in the same browser using local storage and a signed HttpOnly cookie. Jobs and evidence are retained for seven days, with hourly cleanup. Download the evidence bundle from a completed report. It includes source URLs, retrieval times, hashes, page text, search provenance, and accepted claims. Original PDF/HTML bytes are not retained. Bounded D1 artifacts are used for this version; R2 is not required.

Submissions require the access code and same-origin JSON. The private Worker also requires a separate service token. Limits are 10 admitted jobs per UTC day and two active jobs for this installation; each job is terminated by hourly cleanup once older than an hour. These are shared installation limits, not individual user accounts. Keys stay in Worker secrets. Responses are validated, network reads are bounded, source URLs and redirects are restricted to exact issuer hosts, and quoted evidence must match extracted page text. Raw provider errors and credentials are not returned to the browser.

### Deploy

From `src/web`, with Wrangler authenticated to the configured account:

```sh
npm ci
npm run types
npm run research:types
npm run typecheck
npm test
npm run research:test
npx wrangler d1 execute wallstreet-research --remote --file research/schema.sql --config research/wrangler.jsonc
npx wrangler d1 execute wallstreet-research --remote --file reception/schema.sql --config research/wrangler.jsonc
python3 ../../scripts/cloudflare-secrets.py
npm run research:deploy
npm run deploy
```

The secret helper reads `NEBIUS_API_KEY` and `TAVILY_API_KEY` from the repository root `.env`, generates/reuses `.env.cloudflare`, and sends only each Worker's required secrets through Wrangler standard input. It never prints credentials. The model is configured in `research/wrangler.jsonc`. On another account, create a D1 database and replace both account IDs and the database ID before deployment. The frontend must be deployed from its generated `dist/server/wrangler.json`; `npm run deploy` does this.

`npm run research:dev` runs the backend locally. For local integration, put the required secrets in ignored `research/.dev.vars` and `src/web/.dev.vars`, then run both Workers. The legacy `NEBIUS_JOB_SERVICE_URL` adapter remains available when no service binding is configured.

### Job contract

`POST /jobs` accepts `{ "company": "Microsoft", "report_schema_version": 1 }`, requires the internal bearer token, and accepts an `Idempotency-Key` of 8 to 100 letters, digits, underscores, or hyphens. Reusing a key returns the same job; using it for another company returns 409. Admission and access-code consumption use an atomic D1 batch and a trigger, so concurrent submissions cannot exceed two uses. Submission returns promptly with a job ID and queued/running status. `GET /jobs/{id}` returns progress or a schema-validated completed report. `GET /jobs/{id}/evidence` exports artifacts. The public `/api/analyses` routes proxy this contract and enforce the access code and signed job cookie.

## Reception

`components/Reception.tsx` is the homepage assistant. The public same-origin JSON endpoint `/api/reception/{session,chat,code,contact}` creates a signed HttpOnly browser-session cookie and calls the existing private research Worker. Nebius provides structured replies from a bounded project description and the last six server-owned turns. The model can propose only `none`, `access_code`, `navigate`, or `contact`. Navigation resolves to a fixed internal route map. High-confidence prompt overrides are refused before inference; unrelated requests are redirected. Model output never supplies recipient addresses, executable code, arbitrary URLs, or credentials.

Each session can receive one deterministic 96-bit code, valid for 24 hours, with two newly admitted research jobs. Reloading or asking again returns the original code; retries of the same job consume no additional use. D1 stores the code hash, not its plaintext. This is a browser session, not a verified personal identity. Codes also have issuance limits of three per IP per day and 50 globally per day. Chat has a 1,200-character input limit, 30 turns per session, 60 per IP per day, and 600 globally per day, with one pending reply per session. Sessions expire after 24 hours, with stored conversations cleaned up after seven days. Raw access codes are redacted from user messages before storage and inference.

The contact action opens a form. The visitor reviews it and presses **Send message** to confirm. Cloudflare Email Sending is configured for `openwallstreet.zishenchan.com`, with a native binding restricted to sender `reception@openwallstreet.zishenchan.com` and recipient `contact@zishenchan.com`. Visitor email is Reply-To only. There is no extra email API key. Delivery requests have stable IDs, no automatic resend after ambiguous failures, and limits of two messages per session, three per IP per day, and 20 globally per day. Contact records are cleaned up after seven days. The sender domain is enabled and SPF, DKIM, return-path MX, and DMARC DNS records are published. Live mailbox receipt has not been tested; tests use a mock sender.

`/examples/alphabet` retains the existing curated leadership report. `/examples/microsoft` shows the completed paid-account run described above, with a downloadable public bundle containing source text and accepted claims. Full reports no longer appear on the homepage.
